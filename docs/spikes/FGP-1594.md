# FGP-1594 frontend integration spike

This throwaway branch pairs with backend `fgp-1594-spike`. It adds configured
case-list navigation, dedupe summary/group templates and backend reads/saves to
the existing frontend application. Both PRs remain drafts.

The backend owns grouping, assessment policy, cycle validation, completion,
ownership eligibility and all domain decisions. Assessments are fixed for now;
grouping fields and workflow scope remain configured. The backend supplies a BFF
model with headings, links, counts, select options, selected values, disabled
states, historical selections and validation errors. The frontend renders those
fields through Nunjucks/GOV.UK controls and forwards raw form values. It neither
decodes assessment objects nor constructs historical choices. Timeline assessment
text also arrives formatted by the backend.

See `docs/spikes/FGP-1594.md` in the backend branch for the design, Mongo evidence,
agreed configuration lifecycle and implementation ticket outlines. Production
locking and concurrent cycle protection are documented findings, not spike code.

From the backend checkout, this checks the actual frontend routes/templates,
backend HTTP, Mongo persistence, reloaded selections and case timeline:

```sh
FGP1594_FRONTEND=/path/to/this/checkout node scripts/verify-dedupe-spike.js
```

That check substitutes authentication. For manual use, point this frontend at a
backend seeded into a fresh scratch database, sign in as Test ReaderWriter and
open `/cases` → **Clean the list**:

```sh
FG_CW_BACKEND=http://localhost:3201 npm run dev
```

Actual Entra/session/CSRF and browser accessibility coverage remain production
follow-ups. These branches prove feasibility and guide implementation tickets.
